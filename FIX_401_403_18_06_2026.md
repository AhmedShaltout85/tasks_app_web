# Plan: Fix 401/403 Auto-Refresh with Refresh Token

**Date:** 18 June 2026

## Problem Summary

When the access token expires, the app receives a 401/403 error and navigates to the login screen instead of silently refreshing the token via `/auth/refresh-token`. The refresh mechanism code exists but has several bugs that prevent it from working reliably.

## Root Causes Found

| # | Issue | File:Line | Severity |
|---|-------|-----------|----------|
| 1 | `_onTokensRefreshed` is **not awaited** — tokens may not be persisted before retry | `dio_client.dart:137` | HIGH |
| 2 | `clearUserData()` is async but called **without await** in session-expired callback | `user_provider.dart:35` | MEDIUM |
| 3 | 4 logout locations use `clearUserData()` instead of `signOut()` — refresh token not revoked server-side | sidebar, drawers, manager_task_screen | MEDIUM |
| 4 | No diagnostic logging when refresh succeeds/fails — hard to debug | `dio_client.dart` | LOW |
| 5 | `signIn()` silently skips storing refresh token if backend response omits it — no warning | `user_provider.dart:209-213` | LOW |

---

## Step 1: Fix `dio_client.dart` — Await token persistence & add logging

**File:** `lib/newtork_repos/remote_repo/api_repos/dio_client.dart`

**Change A (line 137):** Await the `_onTokensRefreshed` callback so tokens are persisted before retrying:

```dart
// Before:
_onTokensRefreshed?.call(newAccessToken, newRefreshToken);

// After:
await _onTokensRefreshed?.call(newAccessToken, newRefreshToken);
```

**Change B (lines 161-186):** Add detailed logging in both catch blocks to understand why refresh fails:

```dart
// In the DioException catch:
log('DioException during refresh: status=${e.response?.statusCode}, data=${e.response?.data}');

// In the generic catch:
log('Unexpected error during refresh: $e');
```

---

## Step 2: Fix `user_provider.dart` — Await session-expired callback

**File:** `lib/controller/user_provider.dart`

**Change (line 34-36):** The `onSessionExpired` callback calls `clearUserData()` which is async but the callback doesn't await it. Fix by making the callback async:

```dart
// Before:
onSessionExpired: () {
  clearUserData();
},

// After:
onSessionExpired: () async {
  await clearUserData();
},
```

---

## Step 3: Fix inconsistent logout — Replace `clearUserData()` with `signOut()`

**Files (4 locations):**

| File | Line | Change |
|------|------|--------|
| `lib/common_widgets/responsive/app_sidebar.dart` | 202 | `clearUserData()` → `await userProvider.signOut()` |
| `lib/screens/task/manager_task_screen.dart` | 404 | `clearUserData()` → `await userProvider.signOut()` |
| `lib/common_widgets/custom_widgets/custom_drawer.dart` | 224 | `clearUserData()` → `await _userProvider.signOut()` |
| `lib/common_widgets/custom_widgets/custom_user_drawer.dart` | 222 | `clearUserData()` → `await _userProvider.signOut()` |

This ensures the refresh token is always revoked server-side on logout, preventing stale tokens.

---

## Step 4: Add guard in `signIn()` for missing refresh token

**File:** `lib/controller/user_provider.dart`

**Change (after line 213):** Log a warning if the backend response doesn't include a refresh token, so it's immediately obvious why auto-refresh would fail later:

```dart
if (response['refreshToken'] != null) {
  _refreshToken = response['refreshToken'];
  _api.setRefreshToken(_refreshToken!);
  await _saveRefreshTokenToCache(_refreshToken!);
} else {
  log('WARNING: Backend did not return a refreshToken. Auto-refresh will not work.');
}
```
